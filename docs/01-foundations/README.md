# 1. Foundations

Before we talk about types of architecture or how to review one, we need common ground. This section covers what technical architecture actually is, how far it reaches inside a project, and who carries the responsibility for it.

## In this section

1. [What Is Technical Architecture?](what-is-technical-architecture.md) explains what architecture means in practice, and what separates it from design and implementation.
2. [The Scope of Architecture in Technical Projects](scope-of-architecture-in-projects.md) shows where architecture starts and ends in a project, and which decisions belong to it.
3. [The Role of the Architect](role-of-the-architect.md) describes the job itself: the responsibilities, the skills, and most importantly, the loyalties of the person doing the work.

## Why start here

Most failed architecture conversations fail on definitions. If "architecture" means a diagram to one person, a product bundle to another, and a set of expensive decisions to a third, no review can succeed. These three chapters give everyone in the room the same vocabulary.
