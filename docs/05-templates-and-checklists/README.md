# 5. Templates and Checklists

Working tools that turn the earlier sections into practice. Everything here is meant to be copied out and used directly in a real review.

## In this section

1. [Architecture Review Checklist](architecture-review-checklist.md) is the reviewer's question set, organized by the same architecture domains as [Section 2](../02-types-of-architecture/README.md), plus the cross-cutting checks on decision quality and vendor neutrality.
2. [Review Report Template](review-report-template.md) is a ready-to-copy markdown skeleton for delivering findings: context, scope, findings by severity, recommendations, and the follow-through log.
3. [Vendor-Bias Red Flags](vendor-bias-red-flags.md) lists the concrete signals that an "architecture" is really a sales proposal. It works as a pre-signature screening tool, and you do not need to be an architect to use it.

## How to use these

- **Commissioning a review?** Attach the [report template](review-report-template.md) to the engagement scope, so the output format is agreed up front (see the [engagement guide](../04-independent-third-party-review/engaging-independent-reviewers.md)).
- **Performing a review?** Work through the [checklist](architecture-review-checklist.md) domain by domain. The questions map to the "what a reviewer looks for" parts of the [type chapters](../02-types-of-architecture/README.md).
- **Neither, but a big proposal just landed on your desk?** Start with the [red flags](vendor-bias-red-flags.md). It takes twenty minutes and no architecture background.
